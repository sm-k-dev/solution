# NEXORA Architecture

## 1. 현재 WAR

현재 WAR는 JSP 화면과 legacy Bean/DAO class를 포함합니다.

```text
Browser
  ↓
JSP prototype pages
  ↓
(backend MVC 연결 예정)

Legacy classes
├─ member.MemberBean
├─ member.MemberDAO
├─ board.BoardBean
└─ board.BoardDAO
```

`WEB-INF/web.xml`은 Servlet 3.0 descriptor이며 `jdbc/jspdb` JNDI resource-ref가 정의되어 있습니다.

## 2. 목표 MVC

```text
Browser
   ↓
Servlet / Controller
   ↓
Service (필요 기능)
   ↓
DAO
   ↓
JNDI DataSource (jdbc/jspdb)
   ↓
MySQL
   ↓
Servlet
   ↓
JSP View
```

### Controller
Servlet이 요청/파라미터/세션/화면 이동을 담당합니다.

### Model
Bean/DTO/DAO 및 필요한 Service가 데이터와 업무 규칙을 담당합니다.

### View
현재 WAR의 JSP/CSS 디자인을 기반으로 데이터를 표시합니다.

## 3. 기능 영역

```text
NEXORA
├─ Member
├─ Board / Community
├─ Customer Center
├─ SentinelOps
└─ Admin
```

## 4. JNDI

현재 web.xml resource name:

```text
jdbc/jspdb
```

신규 DAO에서도 팀이 JNDI 방식을 유지한다면 같은 이름으로 통일합니다.

## 5. SentinelOps 목표 흐름

```text
Application Error
    ↓
Incident 저장
    ↓
Rule-based Severity
    ↓
Incident 관리
 ├─ 상태/이력
 ├─ AI 보조 분석
 ├─ Slack 알림
 └─ 고객 문의 연결
```

AI는 오류 설명/가능한 원인/대응방안의 보조 수단이며 Severity의 단독 판정 수단으로 사용하지 않습니다.

## 6. DB 관계 개요

```text
member
 ├─ board ─ board_comment
 │        └ board_file
 ├─ inquiry ─ inquiry_file
 └─ incident

incident
 ├─ incident_analysis
 ├─ incident_alert
 ├─ incident_history
 └─ incident_inquiry ─ inquiry
```

상세 구조는 `database/NEXORA_ERD_v4.*`를 참고합니다.
