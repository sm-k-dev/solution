# NEXORA Architecture

## 1. 현재 WAR

기존 JSP 기반 Dynamic Web Project에 회원/게시판/관리자 MVC를 추가했습니다. 일부 `ImportedClasses`와 기존 게시판 화면은 참고용 legacy 파일로 남아 있을 수 있습니다.

```text
Browser
  ↓
Servlet / Controller
  ↓
Service / DAO
  ↓
JNDI DataSource (jdbc/jspdb)
  ↓
MySQL
  ↓
JSP View
```

참고용 legacy 클래스는 `src/main/ImportedClasses`에 보관합니다.

`WEB-INF/web.xml`은 Servlet 3.0 descriptor이며 `jdbc/jspdb` JNDI resource-ref가 정의되어 있습니다.

## 2. 목표 MVC

```text
Browser
   ↓
Servlet / Controller
   ↓
Service (필요 기능)
   ↓
DAO
   ↓
JNDI DataSource (jdbc/jspdb)
   ↓
MySQL
   ↓
Servlet
   ↓
JSP View
```

### Controller
Servlet이 요청/파라미터/세션/화면 이동을 담당합니다.

### Model
Bean/DTO/DAO 및 필요한 Service가 데이터와 업무 규칙을 담당합니다.

### View
현재 WAR의 JSP/CSS 디자인을 기반으로 데이터를 표시합니다.

## 3. 기능 영역

```text
NEXORA
├─ Member
├─ Board / Community
├─ Customer Center
├─ SentinelOps
└─ Admin
```

### 구현된 신규 경로

- `BoardController` (`/board/*`): 게시글 목록/검색/상세/등록/수정/삭제, 댓글/답글, 첨부파일
- `AdminManagementController` (`/admin/members/*`, `/admin/boards/*`): 회원 검색 및 일반 회원 상태 관리, 게시글 숨김 처리
- `AdminAccessFilter` (`/admin/*`): 관리자 세션의 `role=ADMIN` 확인
- 기존 `MemberController`는 관리자 화면 추가를 위해 변경하지 않았습니다. 로그인 조회 DAO는 정지 회원을 제외합니다.

현재 구현은 Tomcat/DB에서 수동 확인 전 단계이며, 요구사항 상태는 `IN_PROGRESS`로 유지합니다.

## 4. JNDI

현재 web.xml resource name:

```text
jdbc/jspdb
```

신규 DAO에서도 팀이 JNDI 방식을 유지한다면 같은 이름으로 통일합니다.

## 5. SentinelOps 목표 흐름

```text
Application Error
    ↓
Incident 저장
    ↓
Rule-based Severity
    ↓
Incident 관리
 ├─ 상태/이력
 ├─ AI 보조 분석
 ├─ Slack 알림
 └─ 고객 문의 연결
```

AI는 오류 설명/가능한 원인/대응방안의 보조 수단이며 Severity의 단독 판정 수단으로 사용하지 않습니다.

## 6. DB 관계 개요

```text
member
 ├─ board ─ board_comment
 │        └ board_file
 ├─ inquiry ─ inquiry_file
 └─ incident

incident
 ├─ incident_analysis
 ├─ incident_alert
 ├─ incident_history
 └─ incident_inquiry ─ inquiry
```

상세 구조는 `database/NEXORA_ERD_v4.*`를 참고합니다.
