# NEXORA 시스템 아키텍처

기준일: 2026-10-06

## 1. 프로젝트 방향

NEXORA는 초기의 종합 Enterprise Solutions 구상에서 보안 전문 서비스로 범위를 조정했습니다.

- 현재 핵심 솔루션: `Web Security`, `SentinelOps`
- 현재 범위 제외: `Web Hosting`, `Web Payment`
- 향후 사업 모델: Web/Network/AI Security API와 SentinelOps API의 무료·유료 구독
- 현재 구현 단계: NEXORA 사이트 내부에서 위협 및 장애를 감지·기록·분류·요약·알림하는 관리형 프로토타입

API Key 발급, 사용량 계측, 요금제 제한은 아직 구현되지 않은 다음 단계입니다.

## 2. 실행 구조

```text
Browser
  ↓
SecurityThreatFilter
  ├─ 웹 요청 위협 검사
  └─ AI 프롬프트 위협 검사
  ↓
IncidentFilter
  └─ 처리되지 않은 예외 및 HTTP 5XX 감지
  ↓
Servlet / Controller
  ↓
Service
  ↓
DAO
  ↓
JNDI DataSource (jdbc/jspdb)
  ↓
MySQL 8.4 (solution)
  ↓
JSP View
```

Security 모니터링 실패가 일반 고객 요청을 중단시키지 않도록 탐지 필터는 fail-open 방식으로 동작합니다. 현재 Security 기능은 위협을 기록하고 관리자에게 보여주는 탐지·관제 기능이며, 네트워크 방화벽이나 WAF처럼 요청을 직접 차단하지는 않습니다.

## 3. MVC 책임

### Controller / Filter

- 요청 파라미터와 세션 검증
- 인증·관리자 권한 확인
- Service 호출과 화면 forward/redirect
- CSRF 토큰 검증
- 공통 오류 및 보안 위협 감지

### Service

- 입력 검증과 상태 전이 규칙
- Severity 및 위협 등급 분류
- AI 분석 요청과 응답 검증
- Slack 알림 및 중복 전송 방지

### DAO / DTO

- JNDI DataSource 기반 DB 접근
- PreparedStatement를 이용한 데이터 처리
- 화면과 Service에서 사용할 DTO 제공

### View

- JSP/JSTL 기반 출력
- 일반 화면은 `inc/top.jsp`, `inc/bottom.jsp` 사용
- 관리자 화면은 `inc/admin-top.jsp`, `inc/admin-bottom.jsp` 사용
- 기능별 CSS와 공통 `top.css` 사용

## 4. 기능 패키지

```text
src/main/java
├─ member       회원가입, 로그인, 마이페이지, 수정, 탈퇴
├─ board        게시글, 댓글, 답글, 첨부파일, 검색, 페이징
├─ inquiry      문의 등록, 내 문의, 관리자 문의 관리
├─ admin        관리자 대시보드, 회원·게시글 관리, 접근 제어
├─ sentinel     5XX 장애 감지, Incident, AI 분석, Slack, 문의 연결
├─ security     웹·AI 위협 감지, 이벤트, 분석, 상태, 알림
└─ common       CSRF 등 공통 보안 기능
```

## 5. SentinelOps 흐름

```text
Java 예외 또는 HTTP 5XX
  → IncidentFilter
  → 규칙 기반 Severity 분류
  → incident 저장
  → CRITICAL Slack 알림
  → 관리자 목록·상세
  → 상태 변경 및 이력
  → OpenRouter 보조 분석
  → 고객 문의 연결·해제
```

Severity는 사람이 정의한 규칙으로 결정합니다. AI는 오류 요약, 가능한 원인, 권장 대응을 작성하는 보조 수단이며 심각도나 상태를 임의로 변경하지 않습니다.

## 6. Security 흐름

```text
HTTP URI·Query·Parameter 또는 AI 입력
  → SecurityThreatFilter
  → 규칙 기반 패턴 탐지
  → 민감정보 마스킹 및 출처 IP 해시
  → 1분 단위 fingerprint 중복 집계
  → security_event 저장
  → CRITICAL Slack 알림
  → 관리자 관제 목록·상세
  → 상태 변경 및 이력
  → OpenRouter 보조 분석
```

현재 탐지 범위:

- Web: SQL Injection, XSS, Path Traversal, Command Injection, SSRF Metadata Access
- AI: Prompt Injection, System Prompt Extraction, AI Tool Abuse, Jailbreak, Prompt 내 민감정보

SentinelOps가 AI에 전송하는 Incident 데이터도 신뢰할 수 없는 입력으로 취급하며, 전송 전 AI 위협 검사와 치환 처리를 수행합니다.

## 7. 관리자 접근 제어

- `/admin/*`: `AdminAccessFilter`가 `role=ADMIN`과 `memberId` 세션을 확인
- `/sentinel/*`, `/security/*`: 각 관리 Servlet이 관리자 세션을 직접 확인
- 상태 변경·분석·일일 요약 POST 요청: CSRF 토큰 검증
- Fetch 요청: 성공 시 `204 No Content`, 일반 요청: redirect

## 8. 데이터베이스 구성

총 15개 테이블을 `database/01_schema.sql` 하나에서 생성합니다.

```text
member
├─ board ─ board_comment
│        └ board_file
├─ inquiry ─ inquiry_file
└─ incident
   ├─ incident_analysis
   ├─ incident_alert
   ├─ incident_history
   └─ incident_inquiry ─ inquiry

security_event
├─ security_event_history
├─ security_analysis
└─ security_alert
```

- 최신 논리 모델: `database/NEXORA_ERD_v5.dbml`
- 통합 샘플 데이터: `database/02_sample_data.sql`
- Security 테이블은 애플리케이션 최초 접근 시에도 `CREATE TABLE IF NOT EXISTS`로 보완 생성됩니다.

## 9. 외부 연동과 설정

| 항목 | 설정 |
|---|---|
| DB | `META-INF/context.xml`의 `jdbc/jspdb` JNDI Resource |
| AI | `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` 환경 변수 |
| Slack | `SLACK_WEBHOOK_URL` 환경 변수 |

실제 값은 Git에 커밋하지 않습니다. AI 또는 Slack 설정이 없어도 DB 기반 핵심 조회·관리 기능은 유지되어야 합니다.
