# 프로젝트 구조 가이드

```text
solution/
├─ database/                         통합 DB 스키마, 샘플, ERD
├─ docs/                             모든 프로젝트·개발·운영 문서
│  ├─ 프로젝트/
│  ├─ 개발/
│  └─ 운영/
├─ tests/                            Java 점검 코드와 API smoke-test 스크립트
└─ src/main/
   ├─ java/
   │  ├─ admin/                      관리자 기능과 권한 필터
   │  ├─ board/                      게시판, 댓글, 첨부파일
   │  ├─ common/                     DB·API·AI·알림·보안·웹 공통 기능
   │  ├─ inquiry/                    문의 등록·관리
   │  ├─ member/                     회원과 탈퇴 보유기간 정리
   │  ├─ security/                   웹·AI 위협 감지와 관제
   │  └─ sentinel/                   장애 감지와 Incident 관리
   └─ webapp/
      ├─ admin/, board/, inc/, inquiry/, member/, security/, solutions/
      ├─ assets/                     CSS, JavaScript, 이미지
      ├─ META-INF/                   JNDI 예시 설정
      └─ WEB-INF/                    web.xml, 라이브러리, 비공개 업로드 경로
```

## 파일 배치 원칙

- Java 소스는 `src/main/java`에 둡니다. 기능 안에서는 `controller`, `service`, `dao`, `dto` 역할을 분리합니다.
- JSP는 `src/main/webapp`의 기능별 디렉터리에 둡니다. 공통 화면 조각은 `inc/`에서 관리합니다.
- REST API Servlet은 화면용 Controller와 분리하고, 공통 응답·인증은 `common/api`에서 관리합니다.
- 모든 문서와 가이드는 `docs/`에 둡니다. `database/`, `tests/`, `WEB-INF/`에는 문서를 중복 저장하지 않습니다.
- DB 기준 SQL과 ERD는 `database/`에 둡니다. 상세 실행 안내는 `docs/운영/데이터베이스_가이드.md`에 둡니다.
- 점검용 Java 소스는 `tests/`에 둡니다. 절차 설명은 `docs/운영/`에 둡니다.
- 실제 `META-INF/context.xml`, 비밀값, 컴파일 결과, Tomcat 임시 파일을 저장소에 추가하지 않습니다.

## 기능 간 공통 사용

| 공통 기능 | 위치 |
|---|---|
| API 인증·JSON 요청/응답·오류 | `common.api` |
| JNDI DataSource | `common.db` |
| OpenRouter 호출 | `common.ai` |
| Slack 알림 클라이언트 | `common.notification` 및 기능별 알림 서비스 |
| CSRF·비밀번호 해시 | `common.security` |
| 사용자 세션·응답 캐시·파일 다운로드 | `common.web` |

신규 기능을 추가할 때 기존 공통 기능이 있으면 해당 패키지에서 재사용하고, 여러 기능에서 반복되는 동작은 먼저 공통 책임과 호출 경계를 확인합니다.
