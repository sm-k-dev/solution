# NEXORA Coding Convention

현재 WAR에는 오래된 FunWeb 코드의 명명 방식(`getBoards`, `userCheck`, `IDcheck`, `reInsertBoard` 등)이 남아 있습니다. 이 코드는 참고 가능한 legacy 코드로 보고, **새로 작성하는 NEXORA 코드는 아래 규칙을 우선 적용**합니다. 기존 코드를 한 번에 이름만 바꾸지는 않습니다. 기능을 실제로 수정/이관할 때 관련 호출부와 함께 안전하게 정리합니다.

## Java

| 대상 | 규칙 | 예 |
|---|---|---|
| Class | PascalCase | `MemberDAO`, `BoardWriteServlet` |
| Method | camelCase + 의미 있는 동사 | `findMemberById()` |
| Variable | camelCase | `memberId`, `boardList` |
| Constant | UPPER_SNAKE_CASE | `MAX_FILE_SIZE` |
| Package | lowercase | `member`, `board`, `incident` |

### Method prefix

| 목적 | 권장 |
|---|---|
| 단건 조회 | `find...` |
| 목록 조회 | `find...List`, `findAll...` |
| 등록 | `insert...` |
| 수정 | `update...` |
| soft delete | `softDelete...` |
| 존재 여부 | `exists...` |
| 개수 | `count...` |
| 검증 | `validate...` |

예:

```java
findMemberById()
findBoardList()
insertBoard()
updateMember()
softDeleteBoard()
existsByEmail()
countBoards()
```

Boolean 메서드는 `is...`, `has...`, `exists...`를 사용합니다.

## DTO / Bean / VO

현재 WAR에는 `MemberBean`, `BoardBean`이 있습니다. 신규 기능에서 DTO/Bean/VO 명칭을 섞지 않도록 기능 단위로 하나를 선택합니다. 기존 Bean을 사용하는 영역은 무리하게 이름만 변경하지 않습니다.

## JSP

현재 WAR의 실제 페이지 구조를 존중합니다.

```text
member/login.jsp
member/signup.jsp
board/board.jsp
board/write.jsp
solutions/sentinelops.jsp
```

새 JSP는 소문자 또는 기존 페이지 naming pattern을 일관되게 따릅니다. URL/파일명 변경은 링크와 Servlet mapping까지 함께 수정합니다.

## CSS / JavaScript

CSS class: `kebab-case`

```css
.board-list
.login-container
.error-message
```

JavaScript variable/function: `camelCase`

## Database

Table / Column: `snake_case`

```text
board_comment
incident_analysis
member_id
created_at
is_deleted
```

PK는 `{entity}_id`, FK는 가능하면 참조 PK 이름을 그대로 사용합니다.

## 상태값

```text
USER / ADMIN
ACTIVE / SUSPENDED / WITHDRAWN
OPEN / ACKNOWLEDGED / RESOLVED
LOW / MEDIUM / HIGH / CRITICAL
```

## Soft Delete

일반 비즈니스 삭제는 NEXORA DB 정책에 따라 `is_deleted`와 `deleted_at`을 우선 사용합니다. 기존 FunWeb DAO의 물리 DELETE는 새 DB 적용 과정에서 기능별로 변경합니다.

## 주석

무엇을 하는지 코드 그대로 반복하기보다 **왜 이 처리가 필요한지** 설명해야 할 때 작성합니다.

## 공통 원칙

- 의미 없는 축약어를 만들지 않습니다.
- 동일 개념은 동일 용어를 사용합니다.
- 공통 규칙 변경은 팀에 공유하고 문서도 함께 갱신합니다.
- legacy 코드와 신규 코드의 차이는 `현재_WAR_분석.md`에 기록합니다.
