# NEXORA Coding Convention

현재 WAR에는 오래된 FunWeb 코드의 명명 방식(`getBoards`, `userCheck`, `IDcheck`, `reInsertBoard` 등)이 남아 있습니다. 이 코드는 참고 가능한 legacy 코드로 보고, **새로 작성하는 NEXORA 코드는 아래 규칙을 우선 적용**합니다. 기존 코드를 한 번에 이름만 바꾸지는 않습니다. 기능을 실제로 수정/이관할 때 관련 호출부와 함께 안전하게 정리합니다.

## Java

### Formatting

- 들여쓰기는 탭 대신 공백 4칸을 사용합니다.
- 한 줄에는 하나의 실행문만 작성합니다.
- 클래스, 메서드, 조건문과 반복문의 여는 중괄호는 선언과 같은 줄에 둡니다.
- `if`, `for`, `while`, `catch`와 여는 괄호 사이에는 공백을 둡니다.
- 메서드와 메서드 사이에는 빈 줄을 한 줄 둡니다.
- 긴 SQL과 문자열 연결은 다음 줄에서 한 단계 더 들여씁니다.
- Eclipse에서는 저장 전 `Source > Format`을 실행합니다.

| 대상 | 규칙 | 예 |
|---|---|---|
| Class | PascalCase | `MemberDAO`, `BoardWriteServlet` |
| Method | camelCase + 의미 있는 동사 | `findMemberById()` |
| Variable | camelCase | `memberId`, `boardList` |
| Constant | UPPER_SNAKE_CASE | `MAX_FILE_SIZE` |
| Package | lowercase | `member`, `board`, `sentinel`, `security` |

### Method prefix

| 목적 | 권장 |
|---|---|
| 단건 조회 | `find...` |
| 목록 조회 | `find...List`, `findAll...` |
| 등록 | `insert...` |
| 수정 | `update...` |
| soft delete | `softDelete...` |
| 존재 여부 | `exists...` |
| 개수 | `count...` |
| 검증 | `validate...` |

예:

```java
findMemberById()
findBoardList()
insertBoard()
updateMember()
softDeleteBoard()
existsByEmail()
countBoards()
```

Boolean 메서드는 `is...`, `has...`, `exists...`를 사용합니다.

## DTO / Bean / VO

현재 WAR에는 `MemberBean`, `BoardBean`이 있습니다. 신규 기능에서 DTO/Bean/VO 명칭을 섞지 않도록 기능 단위로 하나를 선택합니다. 기존 Bean을 사용하는 영역은 무리하게 이름만 변경하지 않습니다.

## JSP

현재 WAR의 실제 페이지 구조를 존중합니다.

```text
member/login.jsp
member/signup.jsp
board/board.jsp
board/write.jsp
solutions/sentinelops.jsp
```

새 JSP는 소문자 또는 기존 페이지 naming pattern을 일관되게 따릅니다. URL/파일명 변경은 링크와 Servlet mapping까지 함께 수정합니다.

- HTML/JSTL 태그는 부모·자식 관계에 따라 공백 4칸으로 들여씁니다.
- 여러 블록 태그를 한 줄에 몰아 작성하지 않습니다.
- 긴 Tailwind 유틸리티 속성은 화면 동작을 보존하기 위해 한 줄을 허용합니다.

## CSS / JavaScript

CSS class: `kebab-case`

```css
.board-list
.login-container
.error-message
```

JavaScript variable/function: `camelCase`

직접 작성한 CSS는 선택자와 선언 블록을 줄바꿈하고 공백 2칸으로 들여씁니다. Tailwind에서 생성한 CSS 번들은 자동 생성 결과를 우선하며 수동으로 재정렬하지 않습니다.

## Database

Table / Column: `snake_case`

```text
board_comment
incident_analysis
member_id
created_at
is_deleted
```

PK는 `{entity}_id`, FK는 가능하면 참조 PK 이름을 그대로 사용합니다.

## Soft Delete

일반 비즈니스 삭제는 NEXORA DB 정책에 따라 `is_deleted`와 `deleted_at`을 우선 사용합니다. 기존 FunWeb DAO의 물리 DELETE는 새 DB 적용 과정에서 기능별로 변경합니다.

## 주석

무엇을 하는지 코드 그대로 반복하기보다 **왜 이 처리가 필요한지** 설명해야 할 때 작성합니다.

## 서버 오류와 예외 처리

SentinelOps의 `IncidentFilter`가 웹 요청 중 처리되지 않은 Java 예외와 HTTP 5xx 응답을 공통으로 기록합니다.

- DB 연결·저장 실패처럼 요청을 정상 완료할 수 없는 서버 오류는 `catch`에서 숨기지 않습니다. 필요한 자원을 정리한 뒤 원인 예외를 포함해 `ServletException`으로 다시 던집니다.
- 오류 메시지에는 **어떤 작업이 실패했는지**만 적습니다. 비밀번호, API 키, 개인 정보 등은 메시지에 포함하지 않습니다.
- 필수 입력 누락, 로그인 실패, 중복 가입처럼 예상 가능한 결과는 검증 후 사용자에게 안내합니다. 일반적인 입력 오류를 서버 장애로 기록하지 않습니다.
- 오류를 다시 던진 뒤 `IncidentRecorder.record()`를 별도로 호출하거나 `sendError(500)`을 추가하지 않습니다. 한 요청이 중복 기록될 수 있습니다.

```java
try {
    boardDao.insertBoard(board);
    response.sendRedirect(request.getContextPath() + "/board/board.jsp");
} catch (SQLException error) {
    throw new ServletException("게시글 저장 중 DB 오류", error);
}
```

이 코드는 Servlet의 예시입니다. 실제 DAO 메서드 이름과 화면 경로는 구현한 기능에 맞춰 사용합니다. 오류를 화면에서 처리하면서 서버 장애로도 기록해야 하는 특수한 경우는 팀장과 기록 방식 및 중복 방지 정책을 먼저 정합니다.

## 공통 원칙

- 의미 없는 축약어를 만들지 않습니다.
- 동일 개념은 동일 용어를 사용합니다.
- 공통 규칙 변경은 팀에 공유하고 문서도 함께 갱신합니다.
- DB 구조 변경 시 통합 스키마와 샘플 데이터, DBML을 같은 커밋에서 갱신합니다.
- 비밀번호, DB 접속 정보, API 키, Slack Webhook URL은 소스와 문서에 직접 기록하지 않습니다.
