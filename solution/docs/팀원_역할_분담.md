# NEXORA 팀원 역할 분담

기준일: 2026-10-07

## 1. 분담 기준

기획서와 주간보고서의 업무분담을 기준으로 5개 기능 영역의 오너를 정리했습니다. SentinelOps와 Security는 같은 이벤트 처리 흐름을 사용하므로 두 기능을 제품별로 쪼개지 않고, **이벤트 탐지·기록 파이프라인**과 **관제·분석·알림·대응**으로 책임을 나눕니다.

아래 표는 계획상 기능 오너와 책임 경계입니다. 실제 참여 인원과 개인별 기여가 다를 수 있으므로 최종 기여 내용은 Git commit·PR, 구현 코드, 테스트 결과를 근거로 확인합니다.

## 2. 팀원별 기능 오너와 책임

## 3. SentinelOps·Security 책임 경계

| 처리 단계 | 담당 | 책임과 산출물 |
|---|---|---|
| 수집·탐지·분류·저장 | 김순민 | 요청/예외 수집, 위협 규칙 검사와 마스킹, 규칙 기반 등급 분류, fingerprint 집계, DAO 저장, 공통 DTO/DAO 계약 |
| 관제·분석·알림·대응 | 유승민 | 관리자 목록·상세 및 상태 관리, AI 보조 분석, Slack 알림·일일 요약, 운영 테스트 |
| 연동 기준 | 공동 협의 | DTO/DAO 계약과 상태·분류값을 먼저 합의하고, 변경 시 상대 담당자와 테스트 기준을 함께 갱신 |

김순민은 SentinelOps만, 유승민은 Security만 맡는 식으로 나누지 않습니다. 두 사람 모두 두 기능의 흐름에 관여하되 처리 단계로 책임을 구분해 중복 구현과 기능 간 단절을 줄입니다.

## 4. 브랜치·통합 원칙

| Branch | 용도 |
|---|---|
| `ksm`, `sm`, `is`, `hw`, `sh` | 개인 작업 브랜치 |
| `team` | 기능 통합, 통합 테스트, 발표 후보 검증 |
| `main` | 최종 검증 후 제출·배포 기준 브랜치. 보호 규칙을 적용하고 직접 작업하지 않음 |

각 담당자는 개인 브랜치에서 작업하고 Pull Request로 `team`에 반영합니다. 통합 담당자는 변경 파일, 실행·테스트 결과, DB·공통 파일 영향 여부를 확인합니다. `team`에서 통합 검증을 마친 뒤에만 승인된 절차로 `main`에 반영합니다.

## 5. 공동 작업과 확인 기준

- `web.xml`, 공통 Java 패키지, DB schema·샘플 데이터, 공통 include/CSS처럼 여러 기능에 영향을 주는 파일은 수정 전에 팀에 공유합니다.
- DB 변경 시 `database/01_schema.sql`, `database/02_sample_data.sql`, ERD와 DB 가이드를 함께 확인합니다.
- 통합 후 회원 세션·관리자 권한·CSRF, Board·Inquiry 연결, SentinelOps·Security 이벤트 흐름을 회귀 테스트합니다.
- 발표 자료와 시연 데이터는 통합 브랜치 기준으로 검증합니다.
- 실제 개인 기여는 계획된 담당 영역만으로 추정하지 않고 commit·PR·소스·테스트 증거로 기록합니다.
