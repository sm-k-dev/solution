# 회원 탈퇴 보유 기간 테스트 가이드

탈퇴 후 3개월이 경과한 회원과 회원이 작성한 데이터가 자동으로 정리되는지 검증합니다. 아래 절차는 반드시 테스트 DB에서만 실행하세요.

## 1. 사전 준비

1. DB를 백업합니다.
2. 기존 DB에 보유 기간 조회 인덱스가 없다면 한 번만 추가합니다.

```sql
ALTER TABLE member
    ADD INDEX idx_member_retention (status, withdrawn_at);
```

3. 삭제 여부를 확인할 테스트 회원을 만들고 게시글, 댓글, 문의, 첨부파일을 작성합니다.

## 2. 3개월 경과 조건 만들기

`cleanup_test` 부분을 실제 테스트 계정의 로그인 ID로 바꿔서 실행합니다.

```sql
SET @cleanup_member_id := (
    SELECT member_id
    FROM member
    WHERE login_id = 'cleanup_test'
);

UPDATE member
SET status = 'WITHDRAWN',
    withdrawn_at = DATE_SUB(NOW(), INTERVAL 3 MONTH)
WHERE member_id = @cleanup_member_id;
```

## 3. 자동 정리 실행

Tomcat을 시작하고 약 1분 후 로그를 확인합니다. 첫 정리 이후에는 24시간마다 반복 실행됩니다.

```text
보유 기간이 끝난 탈퇴 회원 N명을 정리했습니다.
```

## 4. 결과 확인

```sql
SELECT * FROM member WHERE member_id = @cleanup_member_id;
SELECT * FROM board WHERE member_id = @cleanup_member_id;
SELECT * FROM board_comment WHERE member_id = @cleanup_member_id;
SELECT * FROM inquiry WHERE member_id = @cleanup_member_id;
```

모두 0건이어야 합니다. `board_file`, `inquiry_file`의 DB 행과 `WEB-INF/uploads/board`, `WEB-INF/uploads/inquiry` 아래의 실제 파일도 함께 삭제되어야 합니다.

인시던트·보안 이벤트·상태 이력 같은 운영 및 감사 자료는 삭제하지 않습니다. 대신 탈퇴 회원을 가리키는 외래 키만 `NULL`로 변경하여 개인을 특정할 수 없게 처리합니다.

## 5. 미경과 회원 보존 확인

다른 테스트 회원의 `withdrawn_at`을 3개월 미만으로 설정한 후 동일한 절차를 실행합니다.

```sql
UPDATE member
SET status = 'WITHDRAWN',
    withdrawn_at = DATE_SUB(NOW(), INTERVAL 2 MONTH)
WHERE login_id = 'retention_test';
```

이 회원과 작성 데이터는 삭제되지 않아야 합니다.

## 6. 주의사항

- DB 삭제는 트랜잭션으로 처리됩니다.
- 실제 파일 삭제는 DB 커밋 후 수행되므로 파일 시스템 권한 문제가 있으면 로그에 경고가 남고 고립 파일이 남을 수 있습니다.
- 운영 환경에서 시간을 인위적으로 바꾸어 테스트하지 마세요.
