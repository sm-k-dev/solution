# 데이터베이스 가이드

## 관리 파일

| 파일 | 역할 |
|---|---|
| `database/01_schema.sql` | 개발용 DB와 전체 15개 테이블 생성 |
| `database/02_sample_data.sql` | 개발·시연용 샘플 데이터 입력 |
| `database/NEXORA_ERD.dbml` | 논리 ERD 원본 |
| `src/main/webapp/WEB-INF/sql/security_schema.sql` | Security 테이블만 따로 구성할 때 참고하는 보조 SQL |

통합 스키마 `database/01_schema.sql`이 기준 스키마입니다. `SecuritySchema`도 Security 테이블을 `CREATE TABLE IF NOT EXISTS`로 생성하므로 보조 SQL을 통합 SQL과 중복 실행할 필요는 없습니다.

## 새 개발 DB 구성

1. 비어 있거나 초기화해도 되는 **개발용 DB**에서 `database/01_schema.sql`을 실행합니다.
2. 선택적으로 `database/02_sample_data.sql`을 실행합니다.
3. 애플리케이션이 사용하는 JNDI 이름 `jdbc/jspdb`에 DB를 연결합니다. Tomcat 설정 예시는 `src/main/webapp/META-INF/context.xml.example`을 참고하고 실제 접속 비밀값은 로컬 설정에만 둡니다.

> **주의:** `01_schema.sql`은 `solution` DB를 선택하고 기존 테이블을 DROP한 뒤 다시 만듭니다. 기존 데이터가 있는 DB나 운영 DB에서 실행하면 데이터가 삭제됩니다. `02_sample_data.sql`도 반복 실행하면 샘플 행이 중복될 수 있습니다.

## 테이블 구성

총 15개 테이블입니다.

- 회원·커뮤니티·문의: `member`, `board`, `board_comment`, `board_file`, `inquiry`, `inquiry_file`
- SentinelOps: `incident`, `incident_analysis`, `incident_alert`, `incident_history`, `incident_inquiry`
- Security: `security_event`, `security_event_history`, `security_analysis`, `security_alert`

## 데이터 정책 요약

- 사용자 권한은 `member.role`의 `USER` / `ADMIN`으로 구분합니다.
- 회원 상태는 `ACTIVE` / `SUSPENDED` / `WITHDRAWN`입니다.
- 탈퇴 회원은 `withdrawn_at`부터 달력 기준 3개월 후 회원과 작성 콘텐츠·첨부파일을 정리하는 대상입니다. 상세 검증은 [회원 탈퇴 보유 기간 테스트](회원_탈퇴_보유기간_테스트_가이드.md)를 따릅니다.
- Incident 심각도는 규칙으로 분류하고 AI 분석은 보조 정보로만 사용합니다.
- 실제 비밀번호·DB 접속 정보·API 키는 SQL, 문서, Git에 저장하지 않습니다.

## 기존 DB와 스키마 변경

운영 또는 기존 데이터가 있는 DB에는 전체 초기화 스크립트를 실행하지 마세요. 필요한 변경을 별도 검토한 뒤 적용하고, SQL·ERD·애플리케이션 코드를 함께 갱신합니다. `idx_member_retention`은 통합 스키마에 이미 포함되어 있으므로 새 DB에서 별도 `ALTER TABLE`을 실행하지 않습니다.
