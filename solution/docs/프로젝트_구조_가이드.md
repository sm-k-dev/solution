# NEXORA 프로젝트 구조 가이드

```text
solution/
├─ database/                 통합 스키마, 샘플 데이터, ERD
├─ docs/                     협업·코딩·구조·테스트 규칙
├─ tests/                    외부 프레임워크 없는 Java 점검 코드
└─ src/main/
   ├─ java/                  Servlet, Filter, Service, DAO, DTO
   │  ├─ admin/
   │  ├─ board/
   │  ├─ common/               공용 DB·웹·보안·AI·알림 도구
   │  ├─ inquiry/
   │  ├─ member/
   │  ├─ security/
   │  └─ sentinel/
   └─ webapp/                JSP, CSS, JavaScript, WEB-INF 설정
      ├─ inc/                공통 헤더·푸터
      └─ assets/             공통/화면 CSS와 JavaScript
```

## 배치 규칙

- Java 소스는 `src/main/java`에만 둡니다.
- JSP는 기능별 `src/main/webapp/{기능}` 폴더에 둡니다.
- 공통 헤더와 푸터는 `src/main/webapp/inc`를 사용합니다.
- 공통 CSS와 페이지 CSS를 분리하며, 같은 선택자를 페이지별로 다시 정의하지 않습니다.
- Java 컴파일 결과와 Tomcat 임시 파일은 Git에 커밋하지 않습니다.
- 실제 `META-INF/context.xml`은 로컬에서만 만들고 예제 파일만 공유합니다.

## 기능별 책임

| 패키지 | 책임 |
|---|---|
| `security` | 웹 요청·AI 프롬프트 위협 감지, 이벤트, 분석, 알림 |
| `sentinel` | 서버 오류·장애 감지, 인시던트, 분석, 알림 |
| `member` | 로그인, 회원가입, 마이페이지, 탈퇴 |
| `board` | 커뮤니티 게시글, 댓글, 첨부파일 |
| `inquiry` | 사용자 문의와 관리자 답변 |
| `admin` | 관리자 대시보드와 운영 관리 |


## 공통 기능 배치

여러 기능이 같은 기반 처리를 필요로 하면 `common`에 두고 각 기능의 Service/DAO/Controller가 호출합니다. `common`은 도메인 기능을 대신 소유하지 않습니다.

| 공통 위치 | 책임 |
|---|---|
| `common.db.DataSourceProvider` | Tomcat JNDI의 애플리케이션 DB 풀 조회 |
| `common.web.SessionUser` | 로그인 및 관리자 세션 판정 |
| `common.web.WebRequestSupport` | 양수 ID 파싱, fetch/XHR 판별, 변경 응답 처리 |
| `common.web.FileDownloadSupport` | Board/Inquiry의 저장 경로 검증, 안전한 첨부 다운로드 응답 |
| `common.web.CacheControlSupport` | 로그인·관리자 화면 응답의 브라우저 캐시 방지 헤더 |
| `common.security.CsrfTokenManager`, `PasswordHasher` | CSRF 토큰과 비밀번호 해시 |
| `common.notification.SlackWebhookClient` | Sentinel과 Security의 Slack 전송 |
| `common.util.TextUtils` | 알림 문구 단일 행 정리와 길이 제한 |
| `webapp/inc/` | 공통 사이트 헤더·푸터와 관리자 헤더·푸터 |
| `assets/js/admin-actions.js` | 관리자 AJAX 버튼의 공통 전송·오류·확인 처리 |
| `assets/js/private-page.js` | 뒤로가기 캐시에서 복원된 보호 화면을 다시 요청해 세션 권한 재확인 |
| `assets/js/board-replies.js` | 목록·상세 커뮤니티의 공통 답글 선택 처리 |
| `assets/css/common-animations.css` | 여러 랜딩 페이지에서 쓰는 공통 pulse 애니메이션 |
| `assets/css/common-page-reset.css` | 화면 5곳에서 중복되던 공통 body/main 초기화 규칙 |
| `assets/css/common-community.css` | 커뮤니티 목록·상세의 제목·본문 공통 규칙 |
| `assets/css/common-files.css` | 사용자/관리자 문의 상세의 첨부파일 표시 |
| `assets/css/common-page-reset.css` | 공통 페이지 body/main 초기화 규칙 |

예를 들어 게시판이 회원의 계정 상태를 바꾸는 일을 직접 구현하지 않습니다. 회원 계정 변경은 `member` 또는 `admin`의 소유 기능으로 두고, 게시판은 게시글 작성자 식별과 게시판 권한 판단만 담당합니다. 서로 다른 도메인의 SQL과 업무 규칙을 억지로 공유하지 말고, 로그인 판정·DB 풀·전송 같은 횡단 기능만 공통화합니다.

페이지별 Tailwind CSS 파일은 화면별 생성 결과이므로 통째로 합치거나 수작업 재정렬하지 않습니다. 공통 CSS에는 실제 여러 페이지가 함께 사용하는 규칙만 옮깁니다.
