# NEXORA Database Guide

이 디렉터리의 SQL/ERD는 NEXORA DB v5 통합 설계를 기준으로 합니다.

## 파일
- `01_schema.sql`: DB/테이블 생성
- `02_sample_data.sql`: 개발용 샘플 데이터
- `NEXORA_ERD.dbml`: ERD source

## 테이블
`member`, `board`, `board_comment`, `board_file`, `inquiry`, `inquiry_file`,
`incident`, `incident_analysis`, `incident_alert`, `incident_history`, `incident_inquiry`,
`security_event`, `security_event_history`, `security_analysis`, `security_alert`

## 공통 정책
- 관리자: 별도 테이블이 아니라 `member.role = USER/ADMIN`
- 회원 상태: `ACTIVE/SUSPENDED/WITHDRAWN`
- 탈퇴 회원: `withdrawn_at`으로부터 달력 기준 3개월 후 회원 및 작성 데이터 영구 삭제
- 삭제 범위: 회원이 작성한 게시글·댓글·문의와 각 첨부파일
- 운영 감사 데이터: 회원 FK만 `NULL`로 익명화하고 Incident/Security 이력은 보존
- 일반 비즈니스 데이터: `is_deleted + deleted_at` 기반 soft delete
- Incident severity: `LOW/MEDIUM/HIGH/CRITICAL`
- Incident status: `OPEN/ACKNOWLEDGED/RESOLVED`
- Severity는 규칙 기반이며 AI 분석은 보조 정보
- 실제 비밀번호/접속정보는 SQL/문서/Git에 저장하지 않음

## 변경 규칙
공용 DB 구조를 변경했다면 AWS DB만 수정하지 말고 `01_schema.sql`, ERD, 이 문서를 함께 갱신합니다.

기존 DB에는 아래 인덱스를 한 번 추가합니다.

```sql
ALTER TABLE member
    ADD INDEX idx_member_retention (status, withdrawn_at);
```
